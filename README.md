# Колледж ДГУ: Цифровой помощник

Демонстрационная веб-система заявок о проблемах в помещениях Колледжа ДГУ:
QR-код → мобильная форма → заявка в базе → панель сотрудника → отслеживание статуса.

## Что уже работает

- Форма обращения (мобильная, адаптивная), выбор этажа и помещения.
- QR-код для помещения: `/?qr=room214` автоматически подставляет этаж и кабинет.
- Готовый каталог мест: 1 этаж (каб. 101, коридор, столовая, спортзал, актовый зал,
  женская и мужская раздевалки), 2 этаж (каб. 214, коридор), 3 этаж
  (каб. 305, коридор, медпункт), передний двор и задний двор с женским и
  мужским санузлами. Всего 16 мест.
- Управление помещениями и привязкой QR в панели: `/staff/locations`
  (создание и изменение — только администратор).
- Сохранение заявки в базе SQLite с уникальным номером `ДГУ-2026-000001`.
- Секретная ссылка отслеживания `/t/КОД` (в базе хранится только хеш).
- Вход сотрудника и панель колледжа: поиск, фильтры, карточка заявки.
- Смена собственного пароля сотрудником: `/staff/password`.
- Смена статуса, назначение исполнителя, комментарии (публичные и внутренние).
- Приоритеты заявок: низкий, обычный, высокий, срочный; фильтр по приоритету.
- Быстрые ответы сотрудника: «Нужны уточнения», «Передано в работу»,
  «Проблема устранена».
- Необязательные контакты заявителя: телефон и email для уточнения деталей.
- Публичная страница частых вопросов `/faq` из базы знаний помощника.
- Печатная страница QR-табличек `/staff/locations/print`.
- Допустимые переходы статусов: нельзя перескакивать через этапы; возврат из
  «Решена»/«Отклонена» доступен только администратору.
- История изменений статусов.
- Публичная страница отслеживания без внутренних заметок.
- Срок жизни ссылки отслеживания (по умолчанию 90 дней), отзыв, восстановление
  и продление ссылки сотрудником.
- Управление пользователями в админ-панели: создание, роли, сброс пароля,
  отключение и удаление учётных записей без связанных данных.
- Администратор может безвозвратно удалить заявку из её карточки: удаляются
  комментарии, история, вложения и файлы фотографий; действие попадает в аудит.
- Журнал аудита: кто менял помещения/QR, пользователей, статусы и ссылки.
- Статистика с фильтром по датам и экспорт отфильтрованных заявок в CSV
  (UTF-8 BOM, разделитель `;`, защита от формул Excel).
- Генерация QR-кодов: `/qr/room214.png`.
- Демонстрационный ИИ-помощник: проверка текста до отправки, инструкции из базы
  знаний, предложение категории и черновика, отдельная реакция на опасные ситуации.
- Статистика в панели: всего, открытые, решённые, новые, отклонённые, за 30 дней,
  распределение по категориям и помещениям.
- Закрытые вложения: файлы лежат вне `static/` и выдаются только сотруднику или
  заявителю по его секретной ссылке.
- CSRF-защита форм, ограничение попыток входа, лимит хранилища и понятная
  страница ошибки сервера.

## Запуск

```bash
cd /home/mamai/upk
.venv/bin/uvicorn app.main:app --reload
```

Открыть: http://127.0.0.1:8000

Остановить: `Ctrl + C`.

## Запуск, чтобы QR открывался со смартфона

По умолчанию QR-код содержит адрес текущего запроса, то есть `127.0.0.1`.
Телефон по такому адресу не подключится. Укажите сетевой адрес компьютера
в `.env` (скопируйте `.env.example` в `.env`):

```bash
PUBLIC_BASE_URL=http://192.168.1.50:8000
```

Затем запустите сервер так, чтобы он принимал подключения из локальной сети:

```bash
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Телефон и компьютер должны быть в одной Wi-Fi-сети; адрес `192.168.1.50`
замените на IP компьютера. Для реального запуска укажите HTTPS-домен:

```bash
PUBLIC_BASE_URL=https://upk.example.ru
```

Если `PUBLIC_BASE_URL` не задан, страница `/staff/locations` показывает
предупреждение: такие QR-коды не откроются со смартфона.

## Демо-доступ в панель

- администратор (управляет помещениями и QR): `admin` / `admin123`
- сотрудник колледжа (обрабатывает заявки): `staff` / `staff123`

Второй аккаунт нужен, чтобы показать разграничение прав: сотрудник видит
QR-коды и заявки, но не может менять привязку помещения.

При `APP_ENV=production` эти демонстрационные пользователи **не создаются
автоматически**. Если база пустая, администратора нужно создать скриптом
`scripts/create_user.py`. В уже существующей базе старые демо-аккаунты
остаются — их пароли нужно сменить или пользователей удалить.

## ИИ-помощник

Помощник работает **без внешней языковой модели и без API-ключей**. Это
демонстрационная имитация ИИ: текст классифицируется по правилам, а инструкции
берутся из проверенной таблицы `knowledge_base`. Ответы воспроизводимы, а текст
пользователя не отправляется на сторонние сервисы.

Что делает помощник:

- отличает типовой вопрос, неисправность, недостаточное описание и опасную ситуацию;
- для вопроса находит проверенный ответ и указывает источник;
- для неисправности предлагает категорию, черновик описания и оставляет форму открытой;
- при нехватке данных задаёт уточняющий вопрос;
- на неизвестный вопрос честно сообщает, что ответа в базе знаний нет;
- при опасности рекомендует не трогать оборудование и обратиться к ответственному.

Ответ помощника **не создаёт, не закрывает и не меняет статус заявки** — это
подчёркнуто в интерфейсе и проверяется тестами.

API: `POST /assistant/analyze` с JSON `{"text": "..."}`. Ограничения: словарь
правил и база знаний небольшие; помощник не заменяет сотрудника и не даёт
юридических или медицинских консультаций. Для реального запуска вместо имитации
можно подключить внешнюю модель, но ключ должен храниться только на сервере.

## Статистика

Страница `/staff/stats` доступна сотруднику и администратору после входа.
Показатели считаются SQL-запросами по реальным заявкам, без ручных значений:

- всего заявок;
- открытые (все статусы, кроме «Решена» и «Отклонена»);
- решённые;
- новые;
- отклонённые;
- заявки за последние 30 дней;
- распределение по категориям и помещениям с процентами.

Ссылка «Статистика» находится в шапке списка заявок.

## Интерфейс и мобильная версия

- Единый стиль для формы заявителя, входа, списка, статистики и карточки заявки.
- Адаптивная вёрстка: на узких экранах таблица заявок превращается в карточки
  с подписями полей, форма и карточки перестраиваются в одну колонку.
- Кнопки и поля имеют заметный фокус для клавиатуры, добавлена ссылка
  «Перейти к содержимому».
- После смены статуса и добавления комментария показывается подтверждение.
- Пустой результат поиска и ошибки объясняются текстом и действием
  «Сбросить фильтры».
- Некорректный фильтр не вызывает ошибку 500: он сбрасывается с предупреждением.
- В панели отображается общее число заявок и пагинация по 25 записей.
- В шапке есть меню аккаунта: имя и роль сотрудника, панель заявок,
  статистика, помещения и QR, настройки аккаунта и выход.
- Переключатель светлой и тёмной темы в шапке. Выбор запоминается в браузере,
  по умолчанию используется системная тема.

Проверка вёрстки выполнялась на ширинах компьютера и смартфона (360–1440 px)
средствами адаптивных медиазапросов; критичные элементы не выходят за экран.

## Полный сценарий

Автотест `tests/test_e2e.py` проходит цепочку:

`QR → форма → ответ ИИ → заявка с номером → вход сотрудника → назначение исполнителя → статус «Решена» → актуальный статус и комментарий по секретной ссылке`

Дополнительно проверяются:

- доступ в панель без входа;
- опасный и неизвестный запросы к ИИ;
- история статусов;
- отсутствие внутренней заметки на публичной странице.

## Безопасность

- **Вложения закрыты.** Файлы хранятся в `data/uploads/`, а не в `static/`.
  Сотрудник получает их через `/staff/attachment/{id}` после входа, заявитель —
  только через свою ссылку `/t/{token}/attachment/{id}`.
- **CSRF-защита.** Все изменяющие формы содержат токен из сессии: вход, создание
  заявки, смена статуса, комментарии, помещения и выход.
- **Ограничение попыток входа.** После 5 неудачных попыток за 10 минут вход
  временно блокируется. Счётчик хранится в памяти процесса; для нескольких
  экземпляров приложения его нужно вынести в Redis.
- **Ограничение частоты.** С одного IP принимается не более 5 успешных заявок
  за 10 минут и не более 30 запросов к ИИ-помощнику в минуту. Счётчики тоже
  хранятся в памяти процесса.
- **Защита публичной формы.** Honeypot-поле отсекает простых ботов, кнопка
  отправки блокируется от повторного нажатия, длина описания ограничена
  5000 символами.
- **Лимиты текста.** Описание — до 5000 символов, комментарий — до 2000,
  заметка к статусу — до 500.
- **Лимит хранилища.** Один файл — до 5 МБ, общий объём вложений — 200 МБ
  (`MAX_UPLOAD_TOTAL_MB`). Файл проверяется как изображение, имя генерируется
  сервером.
- **Лимит HTTP-запроса.** Всё тело запроса ограничено 12 МБ
  (`MAX_REQUEST_BODY_MB`), проверяются и `Content-Length`, и реально
  прочитанные байты. Фотография читается частями и не загружается в память
  целиком; изображения больше 40 млн пикселей отклоняются.
- **Сессии.** Cookie сессии `HttpOnly` и `SameSite=Lax`. Смена пароля
  увеличивает `session_version` и завершает все старые сессии; отключение
  пользователя тоже сразу закрывает доступ.
- **Кеширование.** Закрытые страницы (`/staff`, `/t/`, `/track`, `/success`,
  `/login`) отдаются с `Cache-Control: no-store`.
- **Логи.** Токены отслеживания редактируются в access-log uvicorn: вместо
  `/t/СЕКРЕТ` пишется `/t/***`, query-параметры `/track` и `/success` скрываются.
- **Права на файлы.** База, вложения и бэкапы доступны только владельцу
  (`600`), каталоги `data/`, `data/uploads/`, `backups/` — `700`. Новые файлы
  создаются с закрытыми правами, в systemd добавлен `UMask=0077`.
- **API-документация.** В `APP_ENV=production` `/docs`, `/redoc` и
  `/openapi.json` отключены.
- **Ошибки сервера.** Необработанная ошибка показывает страницу ошибки и не
  выглядит как успешная отправка заявки.
- **Секреты.** `SECRET_KEY` и настройки читаются из `.env`, который не хранится
  в репозитории. При `APP_ENV=production` приложение не запустится с
  демонстрационным ключом.
- **Заголовки безопасности.** CSP, `X-Frame-Options`, `nosniff`,
  `Referrer-Policy`; HSTS добавляется при HTTPS-настройках.
- **Noindex.** Панель, вход, отслеживание, страница успеха и API помощника
  закрыты заголовком `X-Robots-Tag` и meta-тегом, `/robots.txt` запрещает их
  индексацию.
- **Целостность базы.** SQLite работает с `PRAGMA foreign_keys=ON`, поэтому
  комментарии и вложения не могут ссылаться на несуществующую заявку.
- **Смена пароля.** Сотрудник может сменить свой пароль без правки базы.
  Демонстрационные пароли нужно сменить перед публичным запуском.

### HTTPS перед публичным запуском

Приложение рассчитано на работу за HTTPS-прокси (Caddy, nginx) или на запуск
uvicorn с сертификатом. После настройки HTTPS укажите:

```bash
PUBLIC_BASE_URL=https://upk.example.ru
SESSION_HTTPS_ONLY=1
SECRET_KEY=<длинная случайная строка>
TRUST_PROXY=1
```

Без `SESSION_HTTPS_ONLY=1` cookie сессии может передаваться по HTTP — для
публичного сайта это недопустимо.

`TRUST_PROXY=1` включает доверие заголовку `X-Forwarded-For` и нужен только
за Caddy/nginx. При прямом доступе к uvicorn его включать нельзя: клиент сможет
подделать IP и обойти ограничение частоты.

Полная инструкция: `docs/DEPLOY.md`. В ней — Caddy, systemd, создание
пользователей, смена демо-паролей и резервное копирование.

Готовые примеры и скрипты:

- `deploy/Caddyfile` — HTTPS-прокси с автоматическим сертификатом;
- `deploy/upk.service` — systemd-сервис;
- `scripts/create_user.py` — создание сотрудника или администратора;
- `scripts/backup.py` — ZIP-архив базы и вложений с ротацией.

## Тесты

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/pytest -q
```

Тесты используют отдельную временную базу и временную папку вложений,
не изменяют `data/upk.db` и `data/uploads/`.
Сейчас проверяются 107 сценариев: QR, права, CRUD помещений, ошибки формы,
пять типов ответов ИИ, статистика, CSRF, ограничение входа, закрытые вложения,
смена пароля, заголовки безопасности и полный E2E-сценарий от QR до статуса
«Решена». Отдельные тесты покрывают невалидные фильтры, снятие исполнителя,
комментарий к несуществующей заявке, генерацию номеров, лимиты текста,
honeypot, пагинацию, ограничение частоты заявок и ИИ, внешние ключи SQLite,
production-seed, noindex, favicon, `robots.txt`, HTML/JSON-страницы ошибок,
меню аккаунта и тёмную тему. Новые тесты проверяют управление пользователями,
журнал аудита, срок жизни и отзыв ссылки, переходы статусов, CSV-экспорт,
защиту от формул, фильтр статистики по датам, миграцию старой схемы,
лимит тела запроса, отзыв сессий после смены пароля, редактирование токенов
в логах, безопасное удаление заявок с очисткой файлов, приоритеты, контакты,
быстрые ответы, FAQ и печать QR-табличек.

## База данных

База — SQLite, файл `data/upk.db`. Таблицы создаются автоматически при старте
приложения. Модуль `app/migrations.py` дополнительно проверяет старую схему и
идемпотентно добавляет недостающие колонки (`is_active`, срок и отзыв ссылки),
поэтому обновление существующей базы проходит без ручных действий. Перед
обновлением всё равно рекомендуется сделать бэкап.

### Таблицы

**`users` — сотрудники и администраторы**

| Поле | Назначение |
|---|---|
| `id` | первичный ключ |
| `name` | отображаемое имя |
| `login` | уникальный логин |
| `role` | `staff` или `admin` |
| `password_hash` | PBKDF2-хеш пароля, открытый пароль не хранится |
| `is_active` | `0` — учётная запись отключена, вход запрещён |

**`categories` — справочник категорий**

| Поле | Назначение |
|---|---|
| `id` | первичный ключ |
| `name` | уникальное название категории |
| `description` | пояснение для интерфейса |

**`locations` — помещения и привязка QR**

| Поле | Назначение |
|---|---|
| `id` | первичный ключ |
| `building` | устаревшее служебное поле, в интерфейсе не используется |
| `floor` | этаж |
| `room` | кабинет |
| `zone_name` | название зоны, если это не кабинет |
| `qr_key` | уникальный ключ, который зашит в QR-код |

**`tickets` — заявки**

| Поле | Назначение |
|---|---|
| `id` | первичный ключ |
| `public_number` | уникальный номер вида `ДГУ-2026-000001` (старые заявки могут иметь `УПК-…`) |
| `title` | краткое описание |
| `description` | полный текст обращения |
| `category_id` | ссылка на `categories.id`, может быть пустой |
| `location_id` | ссылка на `locations.id` |
| `status` | текущий статус заявки |
| `priority` | приоритет, по умолчанию «Обычный» |
| `assignee_id` | ссылка на `users.id`, исполнитель |
| `tracking_token_hash` | SHA-256-хеш секретного токена; сам токен в базе не хранится |
| `tracking_expires_at` | до какого времени действует ссылка; пусто — бессрочно |
| `tracking_revoked_at` | когда ссылка была отозвана; пусто — не отозвана |
| `created_at` | дата создания |
| `updated_at` | дата последнего изменения |

Статусы: «Новая», «На рассмотрении», «Назначен исполнитель», «В работе»,
«Нужны уточнения», «Решена», «Отклонена». Переходы между ними ограничены
матрицей в `app/workflow.py`; возврат из итоговых статусов разрешён только
администратору.

**`comments` — комментарии**

| Поле | Назначение |
|---|---|
| `id` | первичный ключ |
| `ticket_id` | ссылка на `tickets.id` |
| `author_id` | ссылка на `users.id` |
| `body` | текст комментария |
| `visibility` | `public` — виден заявителю, `internal` — только сотрудникам |
| `created_at` | дата добавления |

**`ticket_history` — история статусов**

| Поле | Назначение |
|---|---|
| `id` | первичный ключ |
| `ticket_id` | ссылка на `tickets.id` |
| `old_status` | предыдущий статус |
| `new_status` | новый статус |
| `actor_id` | кто изменил статус, ссылка на `users.id` |
| `note` | комментарий к изменению |
| `created_at` | дата изменения |

**`attachments` — вложения заявок**

| Поле | Назначение |
|---|---|
| `id` | первичный ключ |
| `ticket_id` | ссылка на `tickets.id` |
| `storage_key` | имя файла в `data/uploads/` |
| `file_type` | MIME-тип изображения |
| `created_at` | дата загрузки |

Сами файлы лежат в `data/uploads/`, а не в базе и не в `static/`. Доступ к ним
выдаётся только через проверяемые маршруты.

**`knowledge_base` — проверенная база знаний ИИ-помощника**

| Поле | Назначение |
|---|---|
| `id` | первичный ключ |
| `question` | типовой вопрос |
| `answer` | проверенная инструкция |
| `category` | к какой категории относится |
| `source` | источник ответа |
| `updated_at` | дата обновления |

**`audit_log` — журнал действий**

| Поле | Назначение |
|---|---|
| `id` | первичный ключ |
| `actor_id` | кто выполнил действие; обнуляется при удалении пользователя |
| `action` | тип действия: помещение, пользователь, статус, ссылка |
| `entity_type` | тип объекта: `location`, `user`, `ticket` |
| `entity_id` | идентификатор объекта |
| `summary` | короткое описание для интерфейса |
| `details` | подробности в формате JSON (старые и новые значения) |
| `created_at` | дата и время действия |

### Связи

- заявка ссылается на категорию, помещение и исполнителя;
- у заявки много комментариев, записей истории и вложений;
- комментарий и запись истории ссылаются на автора-пользователя;
- удаление заявки каскадно удаляет её комментарии и историю;
- токен отслеживания не хранится в открытом виде — только его хеш.

## Известные недоработки

- Счётчики неудачных попыток входа и частоты запросов хранятся в памяти
  процесса. При запуске нескольких экземпляров приложения их нужно вынести
  в Redis.
- Нет автоматической очистки старых или осиротевших вложений: действует только
  общий лимит хранилища.
- Миграции упрощённые: новые таблицы и колонки добавляются автоматически, но
  сложные изменения (переименование, удаление колонок) по-прежнему требуют
  ручной подготовки и бэкапа.
- SQLite подходит для демонстрации и небольшой нагрузки; для публичного запуска
  с несколькими сотрудниками лучше PostgreSQL.
- ИИ-помощник — демонстрационная rule-based имитация, а не внешняя языковая
  модель. Он не заменяет сотрудника и отвечает только по базе знаний.
- Нет Telegram-уведомлений и email-рассылок — по ТЗ это дополнительные функции
  после MVP. CSV-экспорт уже реализован.
- Загружаемые изображения проверяются на тип, но антивирусная проверка не
  выполняется.
- Адаптивность проверена по контрольным ширинам и структуре страниц, но не на
  реальном смартфоне. Финальную проверку на устройстве нужно сделать вручную.
- Для публичного запуска ещё нужно реально настроить HTTPS, сменить
  демонстрационные пароли и `SECRET_KEY`, а также убедиться, что
  `SESSION_HTTPS_ONLY=1`.
- Нет второго фактора для администратора и автоматического аудита CVE
  зависимостей (`pip-audit`/Trivy).
- CSP пока разрешает inline-скрипты и стили; для максимальной строгости нужны
  nonce/hash и вынос JS в отдельные файлы.
