## 1. Кратко о проекте

- **Название:** «Цифровой помощник Колледжа ДГУ».
- **Назначение:** заявки о проблемах в помещениях и на территории колледжа через QR-код.
- **Путь:** `/home/mamai/upk`.
- **Стек:** Python 3.15.2, FastAPI, SQLite, SQLAlchemy, Jinja2, qrcode, Pillow.
- **GitHub:** приватный репозиторий `femboy-c/upk-digital-assistant`, ветка `main`.
- **Тесты:** `149 passed`.
- **Сервер:** uvicorn на `127.0.0.1:8000`, публично — через временный
  HTTPS-туннель Cloudflare.
- **Адреса:**
  - компьютер: `http://127.0.0.1:8000`
  - публично: `https://kitty-consistent-cgi-notified.trycloudflare.com`
  - проверка: `/health`

Основной сценарий:

`QR → форма → ИИ-помощник → заявка с номером → вход сотрудника → исполнитель → статус → отслеживание по секретной ссылке`

## 2. Запуск, тесты, бэкап

```bash
cd /home/mamai/upk
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
nohup ~/.local/bin/cloudflared tunnel --url http://127.0.0.1:8000 --no-autoupdate \
  > /tmp/opencode/upk-tunnel.log 2>&1 &
```

Адрес туннеля смотрите в логе:

```bash
grep -oE 'https://[a-z0-9-]+\.trycloudflare\.com' /tmp/opencode/upk-tunnel.log | head -1
```

Если порт занят:

```bash
fuser -k 8000/tcp
```

Не использовать `pkill -f "uvicorn app.main:app"` — можно убить свою оболочку.

## 3. Доступ

- Учётная запись `staff` **отключена**, пароль `staff123` больше не работает.
- Учётная запись `admin` активна, но пароль заменён на случайный. Пароль не
  хранится в репозитории и не восстановим из документации.
- Если пароль администратора утерян, нового пользователя можно создать скриптом:

```bash
.venv/bin/python scripts/create_user.py \
  --login admin2 --name "Администратор колледжа" --role admin
```

При `APP_ENV=production` демо-пользователи автоматически не создаются.
Не возвращать `staff/staff123` и `admin/admin123`: эти пароли публично известны.

Схема обновляется автоматически: `app/migrations.py` при старте добавляет
недостающие колонки `users.is_active`, `users.session_version`,
`tickets.tracking_expires_at`, `tickets.tracking_revoked_at`,
`tickets.contact_phone`, `tickets.contact_email`, `tickets.consent_at`,
`tickets.consent_version`, `tickets.merged_into_id` и создаёт таблицу `audit_log`.
Существующие ссылки отслеживания остаются бессрочными, пока их не отзовут вручную.

При старте `seed.py` также добавляет недостающие помещения и удаляет устаревшее
`hall1`; заявки из него переносятся на `corridor-1`.

Все существующие заявки имеют старый префикс `УПК-…`, потому что созданы до переименования. **Новые заявки получают префикс `ДГУ-…`.** Старые номера не переписывались.

У старых заявок нет контактов и отметки согласия на ПДн — они созданы до
появления этих полей. Для новых заявок согласие обязательно, а контакты
необязательны.

## 6. Что уже реализовано

### Публичная часть
- Форма заявки: описание, этаж/территория, помещение, категория, до 5 фото,
  необязательные телефон и email для уточнения деталей.
- Фотографии сжимаются на сервере до 1600 px в JPEG, EXIF удаляется.
- Блок «Как это работает», примеры описаний, счётчик символов, сохранение
  черновика в браузере, превью фото и копирование ссылки после отправки.
- Личный кабинет `/my`: заявки, отправленные или открытые в этом браузере
  (подписанная сессия, до 20 штук; это не замена секретной ссылке).
- Обязательное согласие на обработку ПДн; в заявке сохраняются дата и версия.
- Публичная политика обработки персональных данных `/privacy`.
- QR-код подставляет этаж и помещение.
- Публичная страница частых вопросов `/faq` из базы знаний.
- Номер заявки, секретная ссылка `/t/{token}`.
- Отслеживание статуса, публичные комментарии и история.
- Визуальный прогресс этапов заявки на странице отслеживания.
- Внутренние комментарии не видны заявителю.
- Ограничения длины текста: описание 10–5000, комментарий до 2000, заметка до 500.
- Honeypot-поле, rate limit 5 заявок за 10 минут, защита от двойной отправки.
- Закрытые вложения: `/staff/attachment/{id}` и `/t/{token}/attachment/{id}`.

### Панель сотрудника
- Вход, выход, смена пароля.
- Список заявок: поиск, фильтры, пагинация по 25.
- Некорректные фильтры не дают 500 — сбрасываются с предупреждением.
- Карточка заявки: статус, приоритет, исполнитель, контакты заявителя,
  публичные/внутренние комментарии, история.
- Быстрые ответы: «Нужны уточнения», «Передано в работу», «Проблема устранена».
- Приоритеты: низкий, обычный, высокий, срочный; фильтр по приоритету.
- Исполнителя можно назначить и снять.
- Несуществующий исполнитель и комментарий к несуществующей заявке обрабатываются без 500.
- Статистика: всего, открытые, решённые, новые, отклонённые, за 30 дней, по категориям и помещениям.
- Фильтр статистики по датам и CSV-экспорт отфильтрованных заявок.
- Помещения и QR: просмотр всеми сотрудниками, создание/изменение только администратором.
- Печатная страница QR-табличек `/staff/locations/print`.
- Поиск похожих заявок в карточке и объединение дублей администратором:
  перенос фото, внутренний комментарий и запись в аудит.
- SLA по приоритетам: подсветка просроченных, фильтр `?overdue=1`, карточка
  в статистике, колонка в CSV.
- Массовые действия в списке: назначить исполнителя, сменить приоритет или
  статус до 200 заявок за раз; недопустимые переходы пропускаются.

### Пользователи, аудит и ссылки
- `/staff/users` (только admin): создание, роли, сброс пароля, отключение,
  удаление учётных записей без связанных заявок/комментариев/истории.
- Нельзя отключить или понизить себя и оставить колледж без активного админа.
- `/staff/audit` (только admin): кто и когда менял помещения/QR, пользователей,
  статусы, отзывал/продлевал ссылки; подробности в JSON.
- Администратор может безвозвратно удалить заявку из карточки. Удаляются
  комментарии, история, вложения и файлы фотографий; факт удаления пишется
  в аудит. Обычный сотрудник удалять заявки не может.
- Ссылка отслеживания живёт 90 дней (`TRACKING_LINK_TTL_DAYS`, 0 — бессрочно),
  её можно отозвать, восстановить и продлить из карточки заявки.
- Отозванная/просроченная ссылка и вложения по ней возвращают 404.

### Статусы и экспорт
- Переходы статусов ограничены матрицей `app/workflow.py`.
- Возврат из «Решена»/«Отклонена» доступен только администратору.
- CSV: UTF-8 BOM, разделитель `;`, защита от формул Excel, те же фильтры, что
  у списка заявок, плюс диапазон дат.

### ИИ-помощник
- Работает без внешней модели и API-ключей.
- 5 типов ответов: типовой вопрос, неисправность, недостаточно данных, опасная ситуация, нет ответа.
- Использует таблицу `knowledge_base`, указывает источник.
- Не создаёт, не закрывает и не меняет заявку автоматически.
- Ограничение 30 запросов в минуту с одного IP.

### Интерфейс
- Брендинг «Колледж ДГУ», полное название в подвале.
- Тёмная и светлая темы, выбор запоминается в браузере.
- Меню аккаунта: панель, статистика, помещения, настройки, выход.
- Адаптивная вёрстка: на мобильном «Вход для сотрудника» находится под
  названием колледжа, отдельно от основных ссылок.
- SEO-основа: заголовок и описание с «жалобы ДГУ», canonical, Open Graph,
  JSON-LD, `sitemap.xml`; коды подтверждения Яндекса и Google — в `.env`.

### Безопасность
- CSRF на всех изменяющих формах.
- Ограничение попыток входа: 5 за 10 минут на реальный IP (`CF-Connecting-IP`
  за Cloudflare, затем `X-Forwarded-For`).
- Пароли: PBKDF2-HMAC-SHA256, 600 000 итераций; старые хеши обновляются при входе.
- Для несуществующего логина тоже считается PBKDF2 — нельзя определить логин
  по времени ответа.
- CSP с одноразовым nonce: `script-src` без `unsafe-inline`; inline-обработчики
  `onsubmit`/`onclick` убраны.
- Заголовки `X-Frame-Options`, `nosniff`, `Referrer-Policy`, COOP, CORP,
  `X-Permitted-Cross-Domain-Policies`, HSTS при HTTPS.
- Noindex и `robots.txt` для `/staff`, `/login`, `/track`, `/my`, `/t/`,
  `/success`, `/assistant`.
- Перебор кодов отслеживания: 30 попыток в минуту с IP.
- `PRAGMA foreign_keys=ON`.
- Закрытые вложения и проверка изображения.
- Лимит хранилища 200 МБ, один файл до 5 МБ.
- Лимит всего HTTP-запроса 30 МБ, до 5 фото по 5 МБ, потоковое чтение,
  удаление EXIF, отказ изображениям
  больше 40 млн пикселей.
- `session_version`: смена пароля завершает старые сессии.
- `Cache-Control: no-store` для закрытых страниц.
- Токены отслеживания редактируются в access-log uvicorn.
- В production отключены `/docs`, `/redoc`, `/openapi.json`.
- Версии зависимостей зафиксированы; `pip-audit` не находит известных
  уязвимостей (см. `docs/SECURITY.md`).
- База, вложения и бэкапы закрыты правами `600`, каталоги — `700`.
- Согласие на обработку ПДн фиксируется в заявке (дата и версия политики).
- Закрытые заявки и контакты хранятся `TICKET_RETENTION_DAYS` (по умолчанию
  365 дней), затем удаляются скриптом `scripts/cleanup_old_tickets.py`.

## 10. Ограничения и что осталось

Не реализовано:

- публичной регистрации — её нет намеренно;
- Telegram/email-уведомлений;
- автоматической очистки осиротевших вложений (старые заявки удаляются
  скриптом `scripts/cleanup_old_tickets.py`);
- сложных миграций БД (переименование/удаление колонок) — новые таблицы и
  колонки добавляются автоматически;
- внешней языковой модели (ИИ работает на правилах);
- второго фактора для администратора;
- автоматического аудита CVE зависимостей (`pip-audit`/Trivy);
- полного CSP без `unsafe-inline` (нужны nonce/hash для inline-JS).

Уже реализовано: управление пользователями, аудит изменений QR/помещений,
срок жизни и отзыв ссылки, ограничения переходов статусов, CSV-экспорт и
фильтр статистики по датам, лимит HTTP-запроса и защита от изображений-«бомб»,
отзыв сессий, `no-store`, редактирование токенов в логах, несколько фото
со сжатием, личный кабинет, поиск дублей и объединение, SLA и массовые действия.

Публичный доступ:

- сайт запущен в режиме публичного пилота через временный туннель Cloudflare
  `https://kitty-consistent-cgi-notified.trycloudflare.com` (см.
  `docs/PUBLIC_PILOT.md`);
- включён `APP_ENV=production`, uvicorn слушает только `127.0.0.1:8000`;
- домена и постоянного адреса нет; адрес туннеля меняется при перезапуске;
- для постоянного запуска нужен домен + именованный туннель Cloudflare либо
  VPS/хостинг с Caddy/Let's Encrypt;
- постоянные QR-коды имеет смысл печатать только после получения домена;
- поиск в Яндексе/Google по запросу «жалобы ДГУ» пока невозможен: нужен
  постоянный домен, регистрация в Вебмастере и время на индексацию
  (`docs/SEO.md`).

Ограничения архитектуры:

- rate limit и счётчик входов хранятся в памяти процесса;
- для нескольких workers нужен Redis;
- SQLite подходит для небольшой нагрузки, для роста — PostgreSQL;
- приложение рассчитано на один сервер и reverse proxy Caddy/nginx.

Ручные проверки перед публичным запуском:

- QR камерой реального телефона;
- Safari, Chrome, Firefox;
- экраны 320–360 px;
- смена демо-паролей;
- удаление или замена демо-данных;
- HTTPS, systemd, cron-бэкап;
- проверка восстановления из бэкапа;
- контроль свободного места;
- `TRUST_PROXY=1` за Caddy/nginx;
- перегенерация QR под финальный домен.
